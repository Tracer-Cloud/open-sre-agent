---
title: "AWS ELB"
description: "Connect AWS Elastic Load Balancing so OpenSRE can inspect target group health and backend EC2 instances during investigations."
---

OpenSRE integrates with AWS Elastic Load Balancing (ELB v2) to inspect target group health, identify healthy and unhealthy targets, and map load balancers to the EC2 instances serving traffic.

## Prerequisites

- An AWS account with Elastic Load Balancing (ELB v2)
- AWS credentials configured for the runtime
- Permission to access Elastic Load Balancing resources

## Setup

### Option 1: Interactive CLI

```bash
opensre integrations setup
```

Select **AWS ELB** when prompted.

### Option 2: Environment variables

Add the following to your `.env`:

```bash
AWS_ACCESS_KEY_ID=your-access-key
AWS_SECRET_ACCESS_KEY=your-secret-key
AWS_REGION=us-east-1
AWS_SESSION_TOKEN=your-session-token    # optional
```

| Variable | Required | Description |
| --- | --- | --- |
| `AWS_ACCESS_KEY_ID` | Yes | AWS access key ID |
| `AWS_SECRET_ACCESS_KEY` | Yes | AWS secret access key |
| `AWS_REGION` | No | AWS region (defaults to `us-east-1`) |
| `AWS_SESSION_TOKEN` | No | Session token when using temporary credentials |

## Verify

```bash
opensre integrations verify elb
```

Expected output:

```text
Service: elb
Status: passed
Detail: Successfully connected to AWS Elastic Load Balancing
```

## Investigation tools

When investigating AWS ELB alerts, OpenSRE provides:

- **Target Group Health** — inspect healthy, unhealthy, and draining targets.
- **Backend EC2 Mapping** — identify the EC2 instances registered behind a load balancer.
- **Target Group Summary** — review target health counts and overall availability.
- **Load Balancer Topology** — map load balancers to target groups for investigation.

All operations are read-only.

## Gotcha

Ensure the configured AWS credentials have permission to describe ELB target groups and target health. Without these permissions, backend health information cannot be retrieved even if the load balancer is reachable.

---
title: "AWS ELB"
description: "Connect AWS Elastic Load Balancing so OpenSRE can inspect target group health and backend EC2 instances during investigations."
---

OpenSRE integrates with AWS Elastic Load Balancing (ELB v2) to inspect target group health, identify healthy and unhealthy targets, and map load balancers to the EC2 instances serving traffic.

## Prerequisites

- An AWS account with Elastic Load Balancing (ELB v2)
- AWS credentials configured for the runtime
- Permission to access Elastic Load Balancing resources

## Setup

### Option 1: Interactive CLI

```bash
opensre integrations setup

### Option 2: Environment variables (IAM role)

```bash
AWS_ROLE_ARN=arn:aws:iam::123456789012:role/OpenSREReadOnly
AWS_EXTERNAL_ID=your-external-id     # optional
AWS_REGION=us-east-1
```

### Option 3: Environment variables (static keys)

```bash
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_SESSION_TOKEN=...                # optional
AWS_REGION=us-east-1
```

| Variable | Default | Description |
| --- | --- | --- |
| `AWS_ROLE_ARN` | — | IAM role to assume (recommended) |
| `AWS_EXTERNAL_ID` | — | External ID for role assumption |
| `AWS_REGION` | `us-east-1` | AWS region |
| `AWS_ACCESS_KEY_ID` | — | Static access key (if not using role) |
| `AWS_SECRET_ACCESS_KEY` | — | Static secret key |
| `AWS_SESSION_TOKEN` | — | Session token for temporary credentials |

<Info>
Either `AWS_ROLE_ARN` or `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` is required.
</Info>

## Verify

AWS ELB uses the shared **AWS** integration for authentication. There is no separate `elb` verifier.

```bash
opensre integrations verify aws
```

Verification confirms that the configured AWS credentials are valid through the shared AWS integration. After verification succeeds, ELB investigation tools can inspect target groups and target health.

## Investigation tools

OpenSRE provides the following read-only AWS ELB investigation tool:

- `get_elb_target_health` — retrieve target group information and inspect the health of registered targets behind an Application or Network Load Balancer.

This tool helps identify healthy and unhealthy targets without modifying AWS resources.

## Gotcha

Ensure the configured AWS credentials have permission to describe ELB target groups and target health. Without these permissions, backend health information cannot be retrieved even if the load balancer is reachable.

---
title: "AWS Lambda"
description: "Connect AWS Lambda so OpenSRE can inspect function configuration, invocation logs, and runtime errors during investigations."
---

OpenSRE integrates with AWS Lambda to inspect function configuration, retrieve recent invocation logs from CloudWatch, and investigate runtime failures during incident response.

## Prerequisites

- An AWS account with AWS Lambda functions
- AWS credentials configured for the runtime
- Permission to access Lambda and CloudWatch Logs

## Setup

### Option 1: Interactive CLI

```bash
opensre integrations setup
```

Select **AWS Lambda** when prompted.

### Option 2: Environment variables (IAM role)

```bash
AWS_ROLE_ARN=arn:aws:iam::123456789012:role/OpenSREReadOnly
AWS_EXTERNAL_ID=your-external-id     # optional
AWS_REGION=us-east-1
```

### Option 3: Environment variables (static keys)

```bash
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_SESSION_TOKEN=...                # optional
AWS_REGION=us-east-1
```

| Variable | Default | Description |
| --- | --- | --- |
| `AWS_ROLE_ARN` | — | IAM role to assume (recommended) |
| `AWS_EXTERNAL_ID` | — | External ID for role assumption |
| `AWS_REGION` | `us-east-1` | AWS region |
| `AWS_ACCESS_KEY_ID` | — | Static access key (if not using role) |
| `AWS_SECRET_ACCESS_KEY` | — | Static secret key |
| `AWS_SESSION_TOKEN` | — | Session token for temporary credentials |

<Info>
Either `AWS_ROLE_ARN` or `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` is required.
</Info>

## Verify

AWS Lambda uses the shared **AWS** integration for authentication. There is no separate `aws_lambda` verifier.

```bash
opensre integrations verify aws
```

Verification confirms that the configured AWS credentials are valid through the shared AWS integration. After verification succeeds, Lambda investigation tools can access AWS Lambda resources.

## Investigation tools

OpenSRE provides the following read-only AWS Lambda investigation tools:

- `get_lambda_configuration` — retrieve the configuration of a Lambda function, including runtime, handler, memory, timeout, IAM role, and environment settings.
- `inspect_lambda_function` — inspect Lambda function metadata and deployment information.
- `get_lambda_invocation_logs` — retrieve recent invocation logs from CloudWatch Logs.
- `get_lambda_errors` — retrieve recent Lambda invocation errors.

All operations are read-only and are intended for investigation only.

## Gotcha

Lambda invocation history is retrieved from **CloudWatch Logs**. Ensure the configured AWS credentials have permission to access both **AWS Lambda** and **CloudWatch Logs**, otherwise log retrieval may fail even if Lambda access succeeds.

OpenSRE integrates with Amazon EKS to inspect cluster health, deployment status, managed addons, and Kubernetes workloads during incident investigations.

## Prerequisites

- An AWS account with one or more Amazon EKS clusters
- AWS credentials configured for the runtime
- Permission to access Amazon EKS and the Kubernetes API

## Setup

### Option 1: Interactive CLI

```bash
opensre integrations setup
```

Select **Amazon EKS** when prompted.

### Option 2: Environment variables (IAM role)

```bash
AWS_ROLE_ARN=arn:aws:iam::123456789012:role/OpenSREReadOnly
AWS_EXTERNAL_ID=your-external-id     # optional
AWS_REGION=us-east-1
```

### Option 3: Environment variables (static keys)

```bash
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_SESSION_TOKEN=...                # optional
AWS_REGION=us-east-1
```

| Variable | Default | Description |
| --- | --- | --- |
| `AWS_ROLE_ARN` | — | IAM role to assume (recommended) |
| `AWS_EXTERNAL_ID` | — | External ID for role assumption |
| `AWS_REGION` | `us-east-1` | AWS region |
| `AWS_ACCESS_KEY_ID` | — | Static access key (if not using role) |
| `AWS_SECRET_ACCESS_KEY` | — | Static secret key |
| `AWS_SESSION_TOKEN` | — | Session token for temporary credentials |

<Info>
Either `AWS_ROLE_ARN` or `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` is required.
</Info>

## Verify

Amazon EKS uses the shared **AWS** integration for authentication.

```bash
opensre integrations verify eks
```

(`opensre integrations verify aws` is equivalent.)

Verification confirms the configured AWS credentials through AWS STS. It does not directly verify connectivity to the Kubernetes API. After verification succeeds, OpenSRE can access Amazon EKS resources during investigations.

## Investigation tools

OpenSRE provides the following read-only Amazon EKS investigation tools:

- `describe_eks_cluster` — inspect cluster configuration and status.
- `describe_eks_addon` — inspect managed EKS addons.
- `list_eks_clusters` — list available EKS clusters.
- `list_eks_deployments` — list Kubernetes deployments.
- `get_eks_deployment_status` — inspect deployment health and replica status.
- `list_eks_namespaces` — list namespaces in a cluster.
- `list_eks_pods` — list pods running in a namespace.
- `get_eks_pod_logs` — retrieve logs from a pod.
- `get_eks_events` — inspect Kubernetes events.
- `get_eks_node_health` — inspect node health.
- `get_eks_nodegroup_health` — inspect managed node group health.

All operations are read-only and are intended for investigation only.

## Gotcha

OpenSRE does not require a local `kubeconfig` file.

Instead, it authenticates to Amazon EKS using AWS credentials and creates the Kubernetes client dynamically. Ensure the configured AWS principal has permission to access both Amazon EKS and the Kubernetes API; otherwise workload inspection may fail.

---
title: "Architecture audit tool"
description: "Scan a GitHub repository for architecture violations and get a Markdown audit summary with atomic refactor tasks"
---

The `find_architecture_violations` tool shallow-clones a GitHub repository, runs
architecture scanners, and returns structured findings. The assistant writes the
user-facing **Markdown audit report** in chat from that JSON — the tool does not
return pre-rendered Markdown.

## Tool

| Tool | Role | Side effects |
| --- | --- | --- |
| `find_architecture_violations` | Clone and scan `owner`/`repo` for layer imports, direct imports, compatibility shims, and misplaced modules | None (ephemeral local clone) |

## Typical workflow

1. Ask the assistant to audit a repository, for example: "Scan Tracer-Cloud/opensre
   for architecture issues."
2. The assistant calls `find_architecture_violations` with `owner` and `repo`.
3. The tool returns `violations`, `refactor_tasks`, and `scan_summary` (counts,
   `hotspots`, warnings, skipped categories, `coverage_complete`).
4. The assistant replies with a Markdown report following the tool's
   `AUDIT_REPORT.md` outline: executive summary, coverage, hotspots and
   statistics (from `scan_summary.hotspots`), findings by severity, thematic
   patterns, recommended sequencing, and checks run.

## Parameters

| Parameter | Default | Purpose |
| --- | --- | --- |
| `owner` | required | GitHub organization or user |
| `repo` | required | Repository name |
| `ref` | remote default branch | Branch, tag, or SHA to clone |
| `include_baselines` | `false` | When `true`, report allowlisted import edges instead of suppressing them |
| `strict_layers` | `true` | When `true`, evaluate transitive cross-layer reachability; when `false`, direct edges only |
| `categories` | all scanners | Limit to specific violation kinds |

## Coverage and limitations

- **Layer and direct import checks** use tree-sitter import extraction across supported
  languages (Python, Go, TypeScript/JavaScript, Rust, Java, and more). No import-linter
  config or Python-only layout is required in the target repository.
- **Shims and placement** heuristics are Python/OpenSRE-specific and
  are skipped gracefully when the clone has no relevant Python packages or layout markers.
- When `scan_summary.coverage_complete` is `false`, some categories were skipped or
  warnings were raised — treat results as partial coverage, not proof of a clean repo.
- Layer tiers for unknown repositories are inferred from directory layout; resolution
  quality varies by language and is syntax-level, not type-aware.
- Java/Scala/Kotlin repos use Maven-style `module/src/main/java/...` layout for module
  and package mapping; other JVM layouts may resolve fewer cross-module edges.
- When import resolution is very low, `scan_summary.warnings` notes under-reporting risk.

## GitHub issues

The tool proposes atomic `refactor_tasks` but does not create GitHub issues. To
file issues, ask explicitly; the assistant can use approved GitHub mutation tools
after you confirm.

## Example

```text
Audit Tracer-Cloud/opensre for architecture violations and summarize the top themes.
```

The assistant scans the repo, then returns a Markdown report grouped by severity with
evidence paths and suggested fix order.

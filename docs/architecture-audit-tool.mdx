Architecture audit runs in the **interactive shell** via an action-agent skill.
It is not a chat/investigation tool.

## Workflow

1. `architecture_clone_repo` shallow-clones `owner`/`repo` into
   `.temp/opensre/architecture_workspace`.
2. `scan_architecture_imports` runs polyglot layer/direct import checks
   (contracts inferred from the target repo layout).
3. `scan_module_placement` runs placement heuristics that apply when matching
   patterns exist (e.g. `tools/`, `integrations/`, banned legacy imports);
   other layouts simply yield zero findings with complete coverage.
4. `shell_run` bash heuristics find oversized source files (`wc -l` / similar)
   and likely compatibility shims across languages — not Python-only.
5. `architecture_cleanup_repo` deletes `.temp/opensre/architecture_workspace`.
6. The assistant renders a Markdown audit report from tool JSON + bash output.

## Tools

| Tool | Role |
| --- | --- |
| `architecture_clone_repo` | Clone into `.temp/opensre/architecture_workspace` |
| `scan_architecture_imports` | Layer/direct import violations |
| `scan_module_placement` | Misplaced-module findings |
| `architecture_cleanup_repo` | Delete the architecture workspace only |
| `shell_run` | Oversized + shim heuristics |

## Example

```text
Audit Tracer-Cloud/opensre for architecture violations, including oversized files.
```

The action agent clones, scans, runs the bash passes, cleans up, and returns a
Markdown report shaped by
`core/agent_harness/prompts/skills/architecture_audit/architecture_audit_report.md`.
Size and shim findings are heuristic — treat them as leads, not AST-proof
violations.

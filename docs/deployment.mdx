OpenSRE deploys as a standard Python FastAPI application. Use the repository
`Dockerfile` with Railway, EC2, ECS, Vercel, or another ASGI-capable host. For
local containers, see [Docker](/environments/docker).

The image supports two values of `MODE`:

| `MODE` | Runtime |
| --- | --- |
| `web` (default) | HTTP API — health checks, alert intake, and investigations |
| `gateway` | Messaging gateway (Slack / Telegram) and related services |

## Environment setup

1. Deploy this repository using your host’s normal application workflow, or
   build the `Dockerfile` and set `MODE` to `web` or `gateway`.
2. Set `LLM_PROVIDER` to your model provider (`anthropic`, `openai`,
   `openrouter`, `trustedrouter`, `deepseek`, or `gemini`).
3. Set the corresponding API key:

   - `ANTHROPIC_API_KEY` for `anthropic`
   - `OPENAI_API_KEY` for `openai`
   - `OPENROUTER_API_KEY` for `openrouter`
   - `TRUSTEDROUTER_API_KEY` for `trustedrouter`
   - `DEEPSEEK_API_KEY` for `deepseek`
   - `GEMINI_API_KEY` for `gemini`

4. Add any integration or storage environment variables required by your
   deployment, then verify health with `GET /health` or `GET /ok`.

Minimum configuration:

```bash
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=...
```

Provider keys and optional model overrides are listed in `.env.example` and
[Environment variables](/configuration/environment-variables).

For hosted deployments that need persistent storage, set `DATABASE_URI` and
`REDIS_URI`. The async investigations API uses `DATABASE_URL` for its Postgres
store; see [HTTP API](/api).

## Local gateway

Start a local HTTP server for investigations (and optional chat transports):

```bash
uv run opensre gateway start                 # background daemon
uv run opensre gateway start --foreground    # attached to this terminal
uv run opensre gateway stop
uv run opensre gateway status
```

The web app listens on `0.0.0.0` using the `PORT` environment variable
(default `8000`).

```bash
curl http://127.0.0.1:8000/ok
```

Example investigation request:

```bash
curl -X POST http://127.0.0.1:8000/investigate \
  -H "Content-Type: application/json" \
  -d '{
    "raw_alert": {
      "alert_name": "etl-daily-orders-failure",
      "pipeline_name": "etl_daily_orders",
      "severity": "critical",
      "message": "Orders pipeline failed with timeout."
    }
  }'
```

By default, `/investigate` and `/alerts` accept only loopback callers. To allow
remote access, set `OPENSRE_ALERT_LISTENER_TOKEN` and send it as a bearer token:

```bash
curl -X POST http://127.0.0.1:8000/investigate \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENSRE_ALERT_LISTENER_TOKEN" \
  -d '{"raw_alert":{"alert_name":"test"}}'
```

Complete route reference: [HTTP API](/api).

## Railway

1. Provision Postgres and Redis in the Railway project.
2. Set `DATABASE_URI` and `REDIS_URI` on the OpenSRE service to those connection
   strings.
3. Optionally set `OPENSRE_DEPLOYMENT_METHOD=railway` for telemetry labeling.
4. Deploy the service through your Railway project.

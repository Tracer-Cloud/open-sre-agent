Want to know what OpenSRE actually looks like when you run it? Here's a walkthrough of a first install, the files you get after an investigation, and a way to put your own demos on the page.

## Watch a first run

Install, set things up, and throw a sample alert at it. Most people are done in under ten minutes.

```bash
curl -fsSL https://install.opensre.com | bash
opensre onboard
opensre investigate -i tests/e2e/kubernetes/fixtures/datadog_k8s_alert.json
```

## What you get after a run

When an investigation finishes, OpenSRE drops a few files you can open in any editor:

| File | What's inside |
| --- | --- |
| `problem.md` | What it thought the incident was about, and what looked impacted |
| `theory/hypothesis_*.md` | Each idea it tested, with the evidence for and against |
| `report.md` | The final write-up — likely cause, how sure it is, and what to try next |

Need one file for a script or pipeline instead?

```bash
opensre investigate -i <alert-file> --output ./rca.json
```

## Put it through CloudOpsBench

Curious how OpenSRE stacks up? CloudOpsBench is a 452-scenario Kubernetes RCA suite — you can run OpenSRE against it and compare to published LLM-only baselines.

```bash
uv run python -m tests.benchmarks._framework.cli run \
  --config tests/benchmarks/cloudopsbench/config.yaml \
  --models claude-sonnet-4-20250514
```

Setup, integrity checks, and cost notes live on the [CloudOpsBench page](/cloudopsbench).

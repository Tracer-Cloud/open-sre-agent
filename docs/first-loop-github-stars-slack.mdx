---
title: "First loop: GitHub stars to Slack"
description: "A copy-pasteable checklist for wiring GitHub reads to Slack delivery without touching the OS keyring."
---

The fastest way to see OpenSRE do something useful end to end: read GitHub,
generate a report, and post it to Slack — all using only environment-based
credentials, so it works the same on a laptop, a container, or a headless
server with no OS keyring available.

Requires [OpenSRE installed](/quickstart).

## Checklist

### 1. Configure GitHub (no keyring)

- [ ] Run the setup wizard, which writes your token to the right place for
  your install automatically:

  ```bash
  opensre integrations setup github
  ```

  Choose **paste a token (PAT)** — see [GitHub setup](/github#setup) for
  scopes and the environment-variable alternative if you would rather not run
  the wizard.

- [ ] Verify:

  ```bash
  opensre integrations verify github
  ```

### 2. Configure Slack (no keyring)

- [ ] Create an incoming webhook (see
  [Create a Slack incoming webhook](/messaging/slack#create-a-slack-incoming-webhook)),
  then run:

  ```bash
  opensre integrations setup slack
  ```

  Choose **webhook**. This is the one Slack credential path that never
  touches the OS keyring — see [Slack credentials](/messaging/slack#credentials).

- [ ] Confirm the webhook actually posts before moving on:

  ```bash
  opensre integrations verify slack --send-slack-test
  ```

### 3. Ask for a stars report, delivered to Slack

- [ ] Start the interactive shell **from inside a git checkout of the repo
  you want reported on** (or name the repo explicitly in your prompt — either
  way OpenSRE needs to know which repository you mean):

  ```bash
  opensre
  ```

- [ ] Ask for a report and Slack delivery in one turn, naming the repo:

  ```text
  > get GitHub star velocity for the last 30 days on your-org/your-repo and post it to Slack
  ```

  Replace `your-org/your-repo` with the actual repository. See
  [GitHub workflow tools](/github-workflow-tools) for what this can report on.

### 4. Ask for a work-status report, delivered to Slack

- [ ] Same shell, ask for the check-in report, again naming the repo:

  ```text
  > generate a Slack-ready work status report for your-org/your-repo and post it
  ```

### 5. Confirm Slack delivery

- [ ] Posting to Slack requires approval — confirm the prompt when it
  appears.
- [ ] Check the target Slack channel for the message.

## If something doesn't land in Slack

- **No message in the channel** — re-run `opensre integrations verify github`
  and `opensre integrations verify slack`, and confirm you approved the
  delivery prompt.
- **"GitHub tools unavailable" or an empty report** — the repo could not be
  resolved. Name it explicitly in your prompt (`your-org/your-repo`), or run
  `opensre` from inside that repo's git checkout so OpenSRE can read it from
  `git remote get-url origin`.
- **Token lacks access** — confirm the token has at least `repo` scope (see
  [GitHub setup](/github#setup)).

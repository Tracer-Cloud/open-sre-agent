---
title: "AWS Elasticsearch (AWS ES)"
description: "Connect Amazon OpenSearch Service (AWS ES) so OpenSRE can search application logs during investigations"
---

OpenSRE queries Amazon OpenSearch Service (formerly Amazon Elasticsearch Service, AWS ES) over its REST API to pull error logs and application events into an investigation. This page covers AWS ES specifically; for self-hosted OpenSearch or Elastic Cloud, see the [OpenSearch / Elasticsearch integration](/opensearch).

AWS ES runs the same integration as self-hosted OpenSearch: there's no separate "AWS ES" config, just an `OPENSEARCH_URL` pointed at your domain endpoint.

## Prerequisites

- An Amazon OpenSearch Service (AWS ES) domain
- The domain endpoint URL (e.g. `https://search-mydomain-xxxxx.us-east-1.es.amazonaws.com`)
- Fine-grained access control enabled on the domain, with a master user and password

## Setup

### Environment variables

```bash
OPENSEARCH_URL=https://search-mydomain-xxxxx.us-east-1.es.amazonaws.com
OPENSEARCH_USERNAME=master-user
OPENSEARCH_PASSWORD=master-password
```

| Variable | Default | Description |
| --- | --- | --- |
| `OPENSEARCH_URL` | None | Required. Your AWS ES domain endpoint. |
| `OPENSEARCH_USERNAME` | None | Master user configured on the domain's fine-grained access control. |
| `OPENSEARCH_PASSWORD` | None | Password for the master user. |

Or run `opensre onboard` and pick **OpenSearch / Elasticsearch**.

## Tools

| Tool | What it returns |
| --- | --- |
| `query_elasticsearch_logs` | Log lines matching a query string within a time range, plus a filtered list of lines that look like errors (matches on `error`, `exception`, `timeout`, etc.). |

The tool becomes available to the planner once the OpenSearch source reports `connection_verified`.

## Verify

```bash
opensre integrations verify opensearch
```

## Gotcha

This integration authenticates with HTTP Basic Auth or an API key. It does **not** sign requests with SigV4. If your domain has no fine-grained access control and relies on an IAM-based resource policy instead, unsigned requests are treated as anonymous and rejected with 403 Forbidden. Enable fine-grained access control and use the master user/password shown above.

Analytics pipelines can fail in subtle ways. OpenSRE connects to your Snowflake warehouse to quickly investigate what went wrong — querying your tables, checking warehouse health, analyzing query history, and spotting performance bottlenecks in your data flows.

## Before you start

You'll need:

- A Snowflake account (trial or production)
- A warehouse that's already set up
- Snowflake login credentials (or a service account)
- A database and schema to query against
- Network access from your OpenSRE environment

## Connecting to Snowflake

### The guided way

For a step-by-step walkthrough:

```bash
opensre integrations setup
```

Choose **Snowflake** and answer the prompts.

### The direct way: Environment variables

Or just add these to your `.env`:

```bash
SNOWFLAKE_ACCOUNT=xy12345
SNOWFLAKE_USER=opensre_user
SNOWFLAKE_PASSWORD=your_password
SNOWFLAKE_WAREHOUSE=COMPUTE_WH
SNOWFLAKE_DATABASE=analytics
SNOWFLAKE_SCHEMA=public
SNOWFLAKE_ROLE=viewer
```

| Variable | Default | Description |
| --- | --- | --- |
| `SNOWFLAKE_ACCOUNT` | — | **Required.** Snowflake account identifier |
| `SNOWFLAKE_USER` | — | **Required.** Snowflake username |
| `SNOWFLAKE_PASSWORD` | — | **Required.** Snowflake password |
| `SNOWFLAKE_WAREHOUSE` | — | Warehouse name (e.g., `COMPUTE_WH`) |
| `SNOWFLAKE_DATABASE` | — | Default database |
| `SNOWFLAKE_SCHEMA` | — | Default schema |
| `SNOWFLAKE_ROLE` | — | Database role with appropriate permissions |

## Finding your account ID

Your Snowflake account identifier is easy to find:

1. Open the Snowflake web UI
2. Click your profile avatar (bottom left)
3. You'll see your account ID (looks like `xy12345.us-east-1`)
4. Use just the first part for `SNOWFLAKE_ACCOUNT` (e.g., `xy12345`)

## Best practice: Create a dedicated role for OpenSRE

Instead of using your admin account, create a limited-permission role for better security:

```sql
-- Create a read-only role
CREATE ROLE opensre_viewer;

-- Grant minimal permissions
GRANT SELECT ON ALL TABLES IN DATABASE analytics TO ROLE opensre_viewer;
GRANT MONITOR ON WAREHOUSE COMPUTE_WH TO ROLE opensre_viewer;

-- Create a user for OpenSRE
CREATE USER opensre_user IDENTIFIED BY 'strong_secure_password';

-- Assign the role to the user
GRANT ROLE opensre_viewer TO USER opensre_user;
```

Then use these credentials in your OpenSRE config.

## Stronger security: Key pair authentication

For production, we recommend key pair authentication instead of passwords:

```bash
SNOWFLAKE_ACCOUNT=xy12345
SNOWFLAKE_USER=opensre_user
SNOWFLAKE_PRIVATE_KEY_PATH=/path/to/private_key.pem
SNOWFLAKE_PRIVATE_KEY_PASSPHRASE=your_passphrase
```

This is more secure and easier to rotate.

## Test the connection

Let's verify everything is working:

```bash
opensre integrations verify --id snowflake-prod
```

This checks connectivity and validates your warehouse and database access.

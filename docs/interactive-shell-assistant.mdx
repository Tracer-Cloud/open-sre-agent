---
title: "Assistant with connected tools"
description: "Ask the interactive shell in plain language — it can pull live data from your integrations before answering."
---

In the interactive shell (`opensre`), ask a free-form question. If the answer needs data from a connected integration (GitHub, Datadog, Sentry, Grafana, and others), the assistant calls those tools, gathers results, and answers from that data — not from guesswork alone.

You do not pick a tool or run a slash command for this. Just ask.

## Example

```text
> can you check the github issues for the windows crashes in https://github.com/Tracer-Cloud/opensre?
· gathering via GitHub · search issues — windows crashes…
There are 3 open issues mentioning Windows crashes. The most recent, #482
"App crashes on launch (Windows 11)", reports a startup segfault after the
2.4.0 update…
```

```text
> what do the datadog logs say about payment-service errors in the last hour?
· gathering via Datadog · query logs — payment-service errors…
Found 847 error log lines in the last hour for service:payment-service.
Top pattern: ConnectionTimeout to postgres-primary…
```

The dim `· gathering via …` line shows which integration and tool ran. If the same tool runs more than once, you see `(2)`, `(3)`, and a short query hint.

For GitHub, you can put the repo URL in the question, mention it earlier in the session, set `GITHUB_REPOSITORY`, or let OpenSRE use the current checkout's `origin` remote when GitHub is connected.

## How it works

1. **You ask** a free-form question (not a `/slash` command).
2. **OpenSRE decides** whether live data would help. If yes, it starts a short gather pass — the same registered investigation tools your integrations expose (GitHub search, Datadog logs, Sentry issues, Grafana queries, and so on).
3. **Gathering is bounded** so the shell stays responsive: a few tool-calling rounds, then stop. Large tool results are truncated before they go into the answer prompt.
4. **Tools are read-only data fetches** — they run without a per-call confirmation (same idea as an investigation lookup, not a mutating setup wizard).
5. **Progress** shows on the dim `· gathering via &lt;source&gt; · &lt;tool&gt; — &lt;hint&gt;…` line while tools run.
6. **The assistant answers** using that evidence, plus recent chat context when it matters.

What happens when something goes wrong:

| Situation | Result |
| --- | --- |
| Ctrl+C during gathering | Gather stops; you get a normal text answer without that live data |
| Tool or integration unavailable | That call is skipped; the assistant still answers with what it has |
| No usable tools for the question | No gather pass — text/docs answer only |
| Full RCA needed | Use `/investigate` — this path is for Q&amp;A with live lookups, not a full multi-stage investigation |

This is **not** the same as the investigation pipeline. Investigations plan, loop longer, diagnose, and deliver a report. The assistant gather is a short lookup so a chat answer can cite real data.

## Setup

You need an LLM and at least one integration for live gathering.

**1. LLM**

```bash
opensre onboard
# or set LLM_PROVIDER plus the provider API key — see LLM providers
```

In the shell: `/model show`, `/auth login &lt;provider&gt;` if needed.

**2. Connect integrations**

```bash
opensre integrations setup datadog
opensre integrations setup github
# or in the shell:
/integrations setup
/integrations list
```

Only **connected and verified** integrations contribute tools. If Datadog is not set up, Datadog log questions will not gather from Datadog.

**3. Check that tools are available**

```text
/health          # which integrations look healthy
/verify datadog  # one service
/tools           # tools the assistant/investigation path can use
```

If `/health` is red or `/tools` is empty for that source, fix setup before expecting a gather line.

**4. Ask**

```text
what do the datadog logs say about payment-service errors in the last hour?
```

You should see `· gathering via …` when a tool runs. If you never see it, the question may not need live data, or that integration is not available — re-check `/health` and `/tools`.

With **no** integrations connected, behavior is unchanged: answers come from text and docs only. Connect a source and matching questions start returning live data.

| You ask | Typical source |
| --- | --- |
| Check GitHub issues for Windows crashes | GitHub |
| What do Datadog logs say about payment-service? | Datadog |
| Recent Sentry errors on checkout? | Sentry |
| Error rate in Grafana for prod-api? | Grafana |

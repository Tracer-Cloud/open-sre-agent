## Overview

Forward OpenSRE investigation events into Grafana as:

- Loki log streams (push API)
- Grafana annotations (`/api/annotations`)

Each investigation report becomes a low-cardinality Loki stream, plus an optional Grafana
annotation that summarizes the investigation.

## Prerequisites

- A reachable Loki push URL for Loki mode
- A write token if your Loki requires auth (`GRAFANA_WRITE_TOKEN`)
- For annotations: a configured [Grafana](/grafana) integration with credentials that can create annotations (Editor role or higher)

## Setup

| Variable | Required | Description |
| --- | --- | --- |
| `GRAFANA_LOKI_PUSH_URL` | For Loki push | Full Loki push endpoint (for example `https://<host>/loki/api/v1/push`) |
| `GRAFANA_WRITE_TOKEN` | Optional | Bearer token for Loki push (separate from `GRAFANA_READ_TOKEN`) |

### Option 1: Loki-only mode

You can push to Loki without a Grafana integration record. Set only
`GRAFANA_LOKI_PUSH_URL` (and `GRAFANA_WRITE_TOKEN` if your Loki requires auth).

### Option 2: Annotations via Grafana credentials

When a Grafana integration is configured, OpenSRE uses its credentials (`endpoint`,
`api_key`, or `username`/`password`) to create annotations. Loki-only setups skip
annotations unless a Grafana client is also available.

## Credentials

Loki push uses `GRAFANA_WRITE_TOKEN` when auth is required — keep it separate from
`GRAFANA_READ_TOKEN`. Annotations reuse the Grafana integration credentials (see
[Grafana → Credentials](/grafana#credentials)).

## Investigation tools

This is a reporting sink, not an investigation query tool. It does not expose a query tool
during investigations; it forwards investigation reports to Loki and/or Grafana annotations
after an investigation completes.

## Verify

No dedicated verify command for the log sink. Confirm Loki reachability and write auth in
your environment, and use `opensre integrations verify grafana` when annotations depend on
the Grafana integration.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Loki push fails | Confirm `GRAFANA_LOKI_PUSH_URL` is the full push endpoint and reachable; set `GRAFANA_WRITE_TOKEN` if Loki requires auth. |
| Annotations not created | Ensure a Grafana integration is configured (not Loki-only only); the account needs Editor or higher. |

## Security

| Action | Requirement |
| --- | --- |
| Loki push | Push URL reachable; write token if auth is required |
| Create annotations | Grafana **Editor** role or higher |

Use a dedicated write token for Loki push. Do not reuse a broad admin token when a
narrower write credential exists.

## Extras

### Querying in Grafana Explore

Example LogQL for investigation logs:

```logql
{job="opensre", source="investigation"} | json | severity="critical"
```

```logql
{job="opensre"} | json | alert_name=~".*payments.*"
```

### Annotation tags

Annotations created by OpenSRE include:

| Tag | Meaning |
| --- | --- |
| `opensre` | Produced by OpenSRE |
| `investigation` | Investigation report marker |
| severity (for example `critical`) | Investigation severity |

Filter annotations in Grafana by these tags to find OpenSRE investigations.

# Principal-scoped storage (Slack team installs)

For a **Slack user in a team workspace**, OpenSRE resolves one **principal**
(the Clerk organization that owns the install) and one **actor** (the Slack
user). Team integrations and billing follow the principal. Conversation
sessions follow the actor — the same private context a laptop CLI user keeps
under `~/.opensre`.

Local CLI and Telegram stay on the flat host home when no org scope is bound.

## Who owns the turn

| Context | Principal | Actor |
| --- | --- | --- |
| Slack **team install** | Organization (`clerk_org_id` from install, else silo `OPENSRE_ORGANIZATION_ID`) | Slack user id |
| Other surfaces | Unchanged (not part of this change) | — |

If the install catalog is unreadable, or there is neither an install row nor a
silo org id, the Slack turn is **refused** rather than billed to the wrong owner.

## On-disk layout

A laptop user keeps everything in `~/.opensre`. A Slack member gets the same
thing, filed under their organization, so one gateway can serve several
customers without mixing them.

```text
~/.opensre/
  gateway/…                              # host: state.db, pid, logs
  integrations.json                      # laptop / unbound: unchanged
  sessions/
  memory/
  orgs/<clerk_org_id>/                   # one customer
    integrations.json                    # shared by every member of the org
    members/<slack_user_id>/             # one member's private context
      sessions/<session_id>.jsonl
      memory/
```

Integrations sit at the org root because credentials belong to the team: whoever
connected Datadog, every member investigates with it. Sessions and memory sit
under the member because conversation history is personal, the same way it is on
a laptop.

With no scope bound — a terminal run — every path resolves to the flat
`~/.opensre` layout, unchanged.

The Slack **bot** token used for Socket Mode still comes from the host/env at
process boot (unbound). Per-turn customer tools read the org
`integrations.json` while the scope is bound.

## What changes for Slack

1. Resolve `StorageScope` (`principal` + `actor`) at the start of each Slack turn.
2. Bind the scope for the turn (`bound_storage_scope`).
3. Resolve paths: org home for integrations, member home for sessions.
4. Look up / create session bindings with
   `(platform, chat_id, principal_id, actor_id)`.
5. Consume credits against `principal.id` (the org).

Alice and Bob in the same Slack thread get different session files and different
binding rows. They share the org's integrations store.

## Other surfaces

`principal` and `actor` are optional on the binding store and resolver. Callers
that omit them — Telegram, and anything else on main's path — key bindings by
empty principal/actor ids, which is exactly the behavior they had before.

## Registering a workspace

Nothing in this change writes `slack_installs` rows: there is no OAuth or
control-plane hook yet. Until one exists, give a workspace an owner in one of
two ways.

Set the silo organization, which every workspace without a row falls back to:

```bash
export OPENSRE_ORGANIZATION_ID=org_...
```

Or insert the row directly, which is what a real multi-workspace deployment
needs:

```python
from gateway.storage.slack_installs import upsert_slack_install

upsert_slack_install(team_id="T0123", clerk_org_id="org_...")
```

With neither, a Slack turn from that workspace is refused.

## Upgrading an existing deployment

The bindings table gains `actor_id` (and earlier, `principal_id`). Existing rows
migrate with an empty actor id. The first Slack turn after upgrade creates a
**new per-user binding** (one-time new session for that member/thread). There is
no automatic copy of flat silo `sessions/` or `integrations.json` into
`orgs/<id>/` — copy those once by hand if you need continuity, for example:

```bash
mkdir -p ~/.opensre/orgs/$OPENSRE_ORGANIZATION_ID/members
cp ~/.opensre/integrations.json ~/.opensre/orgs/$OPENSRE_ORGANIZATION_ID/
```

Telegram and other surfaces keep matching their migrated empty-actor rows.

## Related env vars

| Env | Purpose |
| --- | --- |
| `OPENSRE_ORGANIZATION_ID` | Silo org principal when no `slack_installs` row exists yet (dogfood / cutover) |

## Non-goals (this change)

- Remote S3 file storage / CLI Slack emulation
- Per-user integration credentials or LLM auth
- Nesting `opensre.json`, investigations, or REPL history under member homes
- Changing local CLI individual home layout
- Postgres session bindings
- OAuth writer for `slack_installs`

OpenSRE takes an alert or incident description, gathers evidence from your connected tools, and produces a root-cause report.

Before you start: configure an LLM with `opensre onboard`, then set up the
integrations you want checked with `opensre integrations setup`.

## Start an investigation

### Interactive shell

```bash
opensre
```

Then either describe the incident in plain language, or run:

```text
/investigate
/investigate path/to/alert.json
/investigate datadog
```

Bare `/investigate` opens a picker when you're on a TTY. Templates include names like `generic`, `datadog`, and `grafana`. Full slash-command list: [Shell commands](/interactive-shell-commands).

### CLI

```bash
# Alert JSON file
opensre investigate -i path/to/alert.json

# Paste alert JSON in the terminal
opensre investigate --interactive

# Guided menu (demo / template / file / paste)
opensre investigate
```

Useful flags:

| Flag | What it does |
| --- | --- |
| `-i` / `--input` | Alert JSON file |
| `--input-json` | Inline alert JSON string |
| `--interactive` | Paste alert JSON into the terminal |
| `--print-template <name>` | Print a built-in alert template |
| `-o` / `--output` | Write the result JSON to a file |

## What you get

- A report in the terminal (streams on a TTY when you're not writing JSON)
- Machine-readable JSON with `-o ./rca.json` (report, problem framing, root cause, and related fields)
- In the shell after a run: `/last` to show it again, `/save report.md` or `/save rca.json` to write a file
- A short summary to Slack, Telegram, or other chat tools if messaging is configured

## Background runs

In the shell, run `/background on`, then start an investigation. The run continues without blocking the prompt. This is per session only.
